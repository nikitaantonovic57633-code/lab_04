# Лабораторная работа № 4. Алгоритмический мини-пакет

`algo-lab` — устанавливаемый Python-пакет с двумя реализациями чисел Фибоначчи, двумя сортировками, стеком и
генераторами данных. Скрипт benchmark сравнивает время работы сортировок и сохраняет результаты в CSV.

## Установка и запуск

Требуется Python 3.10 или новее. Команды выполняются из корня проекта. Для работы в отдельном окружении в PowerShell:

```
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m algo_lab.benchmark
```

При запуске из корня проекта результаты записываются в `benchmark.csv` рядом с этим README. Каждый запуск
перезаписывает файл в текущем рабочем каталоге.

## Использование

### Числа Фибоначчи

Нумерация начинается с нуля: `F(0) = 0`, `F(1) = 1`. При `n >= 2` выполняется `F(n) = F(n - 1) + F(n - 2)`.

- `fib_iterative(n)` вычисляет результат в цикле, сохраняя два соседних числа.
- `fib_recursive(n)` вычисляет два предыдущих числа рекурсивно. При `n = 0` и `n = 1` возвращает базовое значение.
- Обе функции принимают значения типа `int` от нуля. Отрицательный индекс вызывает `ValueError`, значения других типов,
включая `bool`, вызывают `TypeError`.

Python ограничивает глубину рекурсии. Текущий лимит можно узнать через `sys.getrecursionlimit()`. Когда вызовы
исчерпывают доступную глубину стека, Python выбрасывает `RecursionError`. Прямая рекурсивная реализация выполняет
много повторных вычислений, поэтому на практике она становится медленной задолго до достижения лимита. Для больших
индексов подходит итеративная версия.

### Сортировки

Обе функции принимают `list`, элементы которого имеют тип `int`, и возвращают новый список в порядке возрастания.
Исходный список сохраняет содержимое и порядок. Поддерживаются пустые списки, отрицательные числа и повторы. При
неверном типе входа или его элемента, включая `bool`, возникает `TypeError`.

- `bubble_sort(values)` сравнивает соседние элементы и меняет их местами, если левый больше правого. После каждого
прохода максимальный элемент рабочей части занимает своё место. Проход без обменов завершает сортировку.
- `merge_sort(values)` делит список на половины, рекурсивно сортирует их и сливает. При слиянии индексы продвигаются по
обеим половинам, а при равных значениях первым берётся элемент из левой половины.

### Стек

Стек работает по правилу LIFO: первым извлекается последний добавленный элемент.

| Операция | Назначение |
| --- | --- |
| `push(item)` | Добавляет элемент в стек |
| `peek()` | Возвращает верхний элемент и сохраняет его в стеке |
| `pop()` | Удаляет и возвращает верхний элемент |
| `len(stack)` | Возвращает количество элементов |
| `bool(stack)` | Возвращает `True`, если в стеке есть хотя бы один элемент |

На пустом стеке `peek()` и `pop()` вызывают `IndexError` с сообщением «Стек пуст».

### Генераторы данных

Параметр `size` задаёт количество элементов и предполагается неотрицательным целым числом. При `size = 0` все
генераторы возвращают пустой список.

| Функция | Результат |
| --- | --- |
| `random_list(size, seed=None)` | Случайные числа от `-size` до `size` включительно |
| `sorted_list(size)` | Числа от `0` до `size - 1` по возрастанию |
| `reversed_list(size)` | Числа от `0` до `size - 1` по убыванию |
| `nearly_sorted_list(size, seed=None)` | Возрастающий список с одним обменом соседей при `size >= 2` |
| `duplicate_list(size, seed=None)` | Случайные числа от `0` до `4` включительно |

Генераторы со случайностью создают локальный `random.Random(seed)`. Повторные вызовы с одинаковыми параметрами и
заданным `seed` воспроизводят тот же список.

## Сложность

Для Фибоначчи `n` — индекс числа, для сортировок и генераторов — длина списка.

| Алгоритм или операция | Время | Дополнительная память |
| --- | --- | --- |
| Итеративный Фибоначчи | O(n) сложений | O(1) хранимых чисел |
| Рекурсивный Фибоначчи | O(φⁿ) вызовов, где φ ≈ 1,618 | O(n) кадров рекурсии |
| Пузырьковая сортировка | O(n) в лучшем случае, O(n²) в худшем | O(n) на копию входа |
| Сортировка слиянием | O(n log n) | O(n) для списков и слияния, O(log n) кадров рекурсии |
| Генераторы | O(n) | O(n) на формирование списка |
| `Stack.push`, `Stack.pop` | O(1) амортизированно | O(1) рабочих переменных |
| `Stack.peek`, `len(stack)`, `bool(stack)` | O(1) | O(1) |

Стек занимает O(n) памяти для n элементов. У сортировки слиянием на каждом уровне рекурсии обрабатывается суммарно O(n)
элементов, а глубина деления пополам составляет O(log n). Совокупная пиковая дополнительная память остаётся O(n).

## Benchmark

Использовались размеры **100, 1 000 и 10 000**, пять типов входа и обе сортировки. На каждую комбинацию приходилось
пять повторов. Для случайных генераторов использовался `seed=52`. Оба алгоритма получали одинаковые исходные данные, а
перед каждым повтором создавалась независимая копия. Генерация и подготовка этой копии выполнялись до запуска таймера.
Работа внутри вызова сортировки, включая её собственное копирование списка, входит в замер.

Время измеряется через `time.perf_counter()` в секундах. CSV содержит 30 строк данных и заголовок. Столбцы
`run_1_s`–`run_5_s` содержат пять отдельных замеров.

### Результаты и анализ

В таблице приведено медианное время пяти запусков на списках в обратном порядке.

| Размер | Пузырьковая, с | Слиянием, с |
| ---: | ---: | ---: |
| 100 | 0,000872 | 0,000153 |
| 1 000 | 0,090473 | 0,001798 |
| 10 000 | 7,120901 | 0,016429 |

При увеличении размера с 1 000 до 10 000 время пузырьковой сортировки выросло примерно в 79 раз, а время сортировки
слиянием — примерно в 9 раз. На обратном входе пузырьковая сортировка выполняет n(n − 1) / 2 сравнений. При
десятикратном увеличении размера число сравнений растёт примерно в 100 раз. Время сортировки слиянием растёт
существенно медленнее, что согласуется с оценкой O(n log n). Значения секунд зависят от окружения и не обязаны
повторять теоретические отношения числа операций.

На уже отсортированном списке пузырьковая сортировка завершалась после одного прохода. При увеличении размера со 100 до
1 000 медиана выросла с 0,0000133 до 0,0001334 с, примерно в десять раз. Это согласуется с её линейным лучшим случаем.

## Что проверяют тесты

- Сортировки на пустом списке, одном элементе, возрастающем и обратном наборе, дубликатах и отрицательных числах.
Случайные наборы сравниваются с эталоном `sorted`, который используется в тестах.
- Сохранность исходного списка и возвращение отдельного объекта на непустом примере. Неверные типы вызывают `TypeError`.
- Базовые и обычные значения Фибоначчи, неправильный тип и отрицательный индекс.
- Действия со стеком, порядок LIFO, длина, истинность и исключения при операциях над пустым стеком.
- Пустые наборы, порядок элементов, повторы и воспроизводимость генераторов.
